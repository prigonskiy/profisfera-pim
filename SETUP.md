# PIM — настройка и запуск

Django-проект PIM. Готовы этапы 1 (модель данных) и 2 (админка). Дальше:
динамические категорийные характеристики, JSON-API, деплой.

## Что внутри

```
pim/
├── manage.py
├── requirements.txt        # Django 5.2 LTS, Pillow, tinymce, admin-sortable2
├── .env.example            # пример переменных окружения
├── .gitignore
├── README.md
├── pim/                    # настройки проекта
│   ├── settings.py         # БД, медиа, локаль, редактор — настроено
│   └── urls.py             # /admin/ + отдача медиа в DEBUG
└── catalog/                # основное приложение
    ├── models.py           # ВСЯ модель данных
    ├── admin.py            # админка по всем сущностям
    └── migrations/
        └── 0001_initial.py
```

## Локальный запуск

Нужен Python 3.12+. На Windows — официальный установщик с python.org с
включённой галочкой «Add python.exe to PATH».

```bash
# 1. Создать виртуальное окружение
python -m venv venv          # macOS/Linux: может быть python3

# 2. Активировать его
source venv/Scripts/activate   # Windows (Git Bash)
# source venv/bin/activate     # macOS / Linux

# 3. Поставить зависимости (python -m pip надёжнее, чем просто pip)
python -m pip install -r requirements.txt

# 4. Создать таблицы базы данных
python manage.py migrate

# 5. Создать учётную запись администратора
python manage.py createsuperuser

# 6. Запустить сервер
python manage.py runserver
```

После активации в начале строки терминала появляется `(venv)`. В каждом новом
окне терминала окружение нужно активировать заново (шаг 2). На Windows команда
называется `python` (не `python3`).

Открыть http://127.0.0.1:8000/admin/ — теперь там полноценная админка:
бренды, категории, характеристики, документы и карточки товаров.

> **Обновляетесь с этапа 1?** После `git pull` обязательно повторите
> `pip install -r requirements.txt` — сменилась версия Django (на 5.2 LTS) и
> добавились пакеты редактора и сортировки. Новых миграций модели нет.

## Что умеет админка (этап 2)

- **Товар** — все блоки: изображения с drag-and-drop сортировкой, краткое
  описание, полное описание в визуальном редакторе (TinyMCE), логистика,
  организационный блок, привязка готовых документов.
- **Категории** — с выбором родителя (вложенность).
- **Характеристики** — тип, единица, привязка к категориям, варианты значений
  (для списков) с сортировкой.
- **Бренды**, **документы** (загрузка PDF) — CRUD.

Блок категорийных характеристик в карточке товара появится на этапе 3
(нужна форма, зависящая от выбранной категории).

## Модель данных (кратко)

- **Brand** — бренд: название, slug, логотип, описание.
- **Category** — категория с вложенностью через `parent` (ссылка на себя).
- **Characteristic** — характеристика: 5 типов (single_select, multi_select,
  number, text, boolean), единица измерения, привязка к категориям (M2M),
  машинный `code` для API.
- **CharacteristicOption** — варианты значений для характеристик-списков.
- **Document** — PDF-документ с названием и номером; связь с товарами M2M.
- **Product** — карточка товара: описания (краткое + полное HTML),
  организационный блок (категория, бренд, артикул), логистика (брутто
  ширина/высота/глубина в мм, масса в кг), документы M2M.
- **ProductImage** — изображения товара с полем `order` (для порядка).
- **ProductAttributeValue** — значение категорийной характеристики у товара
  (EAV). Хранит значение в нужном столбце по типу характеристики; уникальность
  пары (товар, характеристика) гарантируется ограничением БД.

## Принятые решения (можно изменить позже)

- **Вложенность категорий** — через self-FK (произвольная глубина). Это просто
  и понятно; при росте каталога можно перейти на django-mptt ради быстрых
  запросов по дереву.
- **Категорийные характеристики не наследуются вниз по дереву**: характеристика
  применяется ровно к тем категориям, к которым привязана явно. Если нужно
  наследование (подкатегория получает характеристики родителя) — это
  добавляется, но логику формы на этапе 3 надо будет учесть.
- **БД по умолчанию — SQLite** для мгновенного старта; на VPS переключим на
  Postgres переменной `DB_ENGINE=postgres`.
