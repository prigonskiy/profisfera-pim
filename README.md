# ProfiSfera PIM — управление товарной информацией

Headless PIM для интернет-магазина стоматологических материалов и инструментов
на Django + DRF. Хранит и редактирует каталог (товары, бренды, категории с
вложенностью, характеристики, варианты, документы, обучение) через админку и
отдаёт его во внешний JSON-API. Витрина — отдельный статический сайт, который
собирается из этого API (см. [«Связанная витрина»](#связанная-витрина)).

Поверх каталога есть коммерческий слой (торговые предложения, цены по каналам,
клиенты/юрлица) — он **приостановлен** на время проработки интеграции с внешней
платформой; ядром-источником остаётся контент. Контракт контента для интеграции
описан в [INTEGRATION.md](INTEGRATION.md).

## Как устроено

Редактор работает в админке → данные лежат в БД → REST-API отдаёт каталог на
чтение. Публичная витрина `profisfera-shop` не ходит в БД напрямую: она
собирается в статику из API и пересобирается по требованию (кнопкой в админке
или командой). Таким образом PIM — единственный источник правды о товарах,
а витрина — его закешированный снимок.

## Стек

- Python 3.12+, Django 5.2 LTS, Django REST Framework.
- `django-mptt` — дерево категорий; `django-admin-sortable2` — сортировка
  перетаскиванием; `django-tinymce` — визуальный редактор описаний;
  `django-countries` — страна происхождения; `django-cors-headers`;
  `django-image-uploader-widget` — загрузчик изображений товара;
  `drf-spectacular` — OpenAPI-схема; `openpyxl` — Excel; `psutil` — метрики
  сервера; `Pillow`; `python-slugify` + `text-unidecode` — транслитерация slug;
  `python-dotenv`.
- На продакшене: PostgreSQL, gunicorn, nginx, HTTPS (Let's Encrypt).

## Модель данных

Приложение `catalog`; модели разнесены по файлам (`models.py` — каталог,
`offers.py`, `clients.py`, `education.py`) и подключаются в `models.py` одной
строкой импорта.

**Каталог (`models.py`)**

- **Brand** — бренд (название, slug, логотип, описание).
- **Category** — категория, дерево на `django-mptt` (перетаскивание и
  переподчинение в админке).
- **Characteristic** / **CharacteristicOption** — характеристики пяти типов, с
  единицей измерения, привязкой к категориям, флагами «глобальная» и
  «показывать покупателю»; `admin_label` — внутренняя пометка для разборчивости.
- **CategoryFilter** — какая характеристика и в каком виде работает фильтром в
  категории; **наследуется вниз по дереву** (потомок переопределяет предка).
- **Product** — товар: описания, категория, бренд, артикулы (авто-`sku` +
  артикул производителя), GTIN, ТН ВЭД, страна, логистика брутто, изображения,
  документы, привязка к серии/уровню вариантов, навигационные фасеты. Поле
  `external_id` удалено (миграция 0023) — код сопоставления с ERP живёт на
  торговых предложениях (`Offer.erp_code`), ключ интеграции контента — `sku`.
- **ProductImage** — изображения товара с порядком.
- **ProductAttributeValue** — значения характеристик у конкретного товара (EAV).
- **Document** — PDF-документы (тип, номер, орган выдачи, сроки, бессрочность),
  привязка M2M к товарам.
- **ProductGroup** / **GroupLevel** — серии вариантов: товар входит в одну серию
  и один её уровень (FK `Product.group_level`) — однозначная группировка.
- **Audience** / **Direction** — навигационная таксономия (для кого / для чего).
- **SkuCounter** — счётчик автогенерации внутренних артикулов.

**Коммерческий слой (`offers.py`) — принцип «один остаток, много цен» (пауза)**

- **Seller** → **Warehouse** (с обслуживаемыми регионами) → **Offer** (остаток +
  `erp_code` на складе, unique(warehouse, product)) → **OfferTerm** (строка
  «канал × единица» с ценой поверх одного остатка). **Region** — справочник
  субъектов РФ.

**Клиенты (`clients.py`) — пауза**

- **Client** (email + хеш пароля), **LegalEntity** (ИНН, сегмент-канал),
  **ClientMembership** (привязка, подтверждается в админке), **ClientToken**.

**Обучение (`education.py`)**

- **Course** (свой набор товаров M2M) → **CourseModule** (слайды/видео/лонгрид)
  → **Slide**.

## API

База: `/api/` (DRF, браузерный интерфейс там же). Пагинация по 20, троттлинг
анонимных (ставки — в `.env`). Чтение публичное, запись — только staff по токену
(`IsStaffOrReadOnly`). Полная спецификация — OpenAPI (см. ниже).

**Схема и документация**
- `GET /api/schema/` — OpenAPI 3 (YAML); `GET /api/docs/` — Swagger UI.

**Товары**
- `GET /api/products/` — список (фильтры `category`, `brand`, `audience`,
  `direction`, `sku`, `sku__in`, `search`, `ordering`, `updated_since`).
- `GET /api/products/{slug}/` — карточка (адресуется по `slug` или `sku`).
- `GET /api/products/by-sku/{sku}/` — карточка по ключу интеграции контента.
- `GET /api/products/by-external-id/{code}/` — по коду ERP продавца
  (коммерческий слой; для контента используйте `by-sku`).

**Справочники**
- `GET /api/categories/`, `.../tree/`, `.../{slug}/filters/`.
- `GET /api/brands/`, `GET /api/characteristics/`, `GET /api/documents/`.
- `GET /api/audiences/`, `.../menu/`, `GET /api/directions/`.

**Приватный слой (пауза)**
- `POST /api/auth/login/`, `/logout/`, `GET /api/auth/me/`,
  `GET /api/products/{slug}/pricing/` — цены по каналам клиента (аноним → розница).

## Админка

- **Дашборд** на главной — сводка по серверу (CPU, память, диск), staff-only
  эндпоинт `/server-metrics/`, обновление раз в 5 с.
- Разделы (`admin_grouping.py`): Каталог, Торговые предложения, Обучение,
  Клиенты и юрлица.
- **Категории** — дерево с перетаскиванием (`DraggableMPTTAdmin`) и кнопка
  «Пересобрать витрину».
- **Сортировка перетаскиванием** у брендов, характеристик, аудиторий и уровней.
- **Визуальный редактор** описаний (TinyMCE) с загрузкой картинок; отдельный
  загрузчик изображений товара.
- **Редактор группировки вариантов** — SPA с drag-and-drop.
- **Экспорт/импорт каталога в Excel** — кнопки на списке товаров.
- Динамическая форма характеристик по категории; автогенерация SKU;
  транслитерация slug.

## Команды

- `python manage.py import_catalog products.json [--dry-run]` — импорт из старой
  JSON-выгрузки.
- `python manage.py sync_offers [--demo | --source URL/файл | --seller]` — синк
  остатков/цен торговых предложений.
- `python manage.py documents_expiring [--days N]` — отчёт по срокам документов.
- `python manage.py rebuild_storefront` — пересборка витрины из CLI/крона.

## Быстрый старт (локально)

Подробно — в [SETUP.md](SETUP.md). Коротко: venv →
`pip install -r requirements.txt` → `migrate` → `createsuperuser` →
`runserver` → http://127.0.0.1:8000/admin/ (и `/api/docs/` для контракта).

## Рабочий процесс и деплой

Разработка локально → коммит и `push` в `main` → деплой на VPS
(см. [DEPLOY.md](DEPLOY.md)). Через git едут **только код и миграции**; БД и
`media/` у каждой среды свои. Секреты — в `.env`; на проде `DEBUG=0`.

## Связанная витрина

`profisfera-shop` — статическая витрина (SSG на GitHub Pages), собирается из
этого API. Пересборка — кнопкой «Пересобрать витрину» в админке или командой
`rebuild_storefront` (технически `repository_dispatch` в GitHub Actions витрины).
