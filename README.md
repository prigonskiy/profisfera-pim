# ProfiSfera PIM — управление товарной информацией

Headless PIM для интернет-магазина стоматологических материалов и инструментов
на Django + DRF. Хранит и редактирует каталог (товары, бренды, категории с
вложенностью, характеристики, варианты, документы) через админку и отдаёт его
во внешний JSON-API. Витрина — отдельный статический сайт, который собирается
из этого API (см. [«Связанная витрина»](#связанная-витрина)).

## Как устроено

Редактор работает в админке → данные лежат в БД → REST-API отдаёт каталог на
чтение. Публичная витрина `profisfera-shop` не ходит в БД напрямую: она
собирается в статику из API и пересобирается по требованию (кнопкой в админке
или командой). Таким образом PIM — единственный источник правды о товарах,
а витрина — его закешированный снимок.

## Стек

- Python 3.12+, Django 5.2 LTS, Django REST Framework.
- `django-mptt` — дерево категорий; `django-admin-sortable2` — сортировка
  перетаскиванием; `django-tinymce` — визуальный редактор описаний;
  `django-countries` — страна происхождения; `django-cors-headers`;
  `django-image-uploader-widget` — загрузчик изображений товара;
  `openpyxl` — Excel; `psutil` — метрики сервера; `Pillow`;
  `python-slugify` + `text-unidecode` — транслитерация slug; `python-dotenv`.
- На продакшене: PostgreSQL, gunicorn, nginx, HTTPS (Let's Encrypt).

## Модель данных

Всё живёт в приложении `catalog`:

- **Brand** — бренд (название, slug, логотип, описание).
- **Category** — категория, дерево на `django-mptt` (родитель → потомки,
  перетаскивание и переподчинение в админке).
- **Characteristic** / **CharacteristicOption** — характеристики пяти типов
  (текст, число, булево, список значений и т. п.), с единицей измерения,
  привязкой к категориям, флагами «глобальная» и «показывать покупателю».
- **CategoryFilter** — какая характеристика и в каком виде (чекбоксы, диапазон…)
  работает фильтром в конкретной категории; настройки вида — в JSON-поле.
- **Product** — товар: описания (краткое + полное), категория, бренд,
  артикулы (свой авто-SKU и артикул производителя), внешний ID, GTIN, код ТН ВЭД,
  страна происхождения, габариты и вес брутто (логистика), изображения,
  документы, привязка к варианту/группе и к маркетинговой таксономии.
- **ProductImage** — изображения товара с порядком.
- **ProductAttributeValue** — значения характеристик у конкретного товара.
- **Document** — PDF-документы (тип, номер, орган выдачи, сроки, бессрочность),
  привязка многие-ко-многим к товарам.
- **ProductGroup** / **GroupLevel** / **GroupLevelValue** / **ProductGroupValue** —
  система вариантов: товары объединяются в группу с осями (напр. «Тип», «Цвет»),
  у каждого товара — свои значения по осям.
- **Audience** / **Direction** — маркетинговая таксономия (для кого / для чего).
- **SkuCounter** — счётчик для автогенерации внутренних артикулов.

## API

База: `/api/` (DRF, браузерный интерфейс доступен там же). Пагинация по 20,
троттлинг анонимных запросов (ставки — в `.env`). Чтение — публичное, запись
(POST/PUT/PATCH/DELETE) — только для staff или по токену (`IsStaffOrReadOnly`).
Аутентификация — токен или сессия; вход в браузерный API — `/api-auth/`.

- `GET /api/products/` — список; `GET /api/products/{slug}/` — карточка;
  `GET /api/products/by-external-id/{code}/` — поиск по внешнему ID.
- `GET /api/categories/` — список; `GET /api/categories/tree/` — дерево целиком;
  `GET /api/categories/{slug}/filters/` — фильтры-фасеты категории.
- `GET /api/brands/`, `GET /api/brands/{slug}/`.
- `GET /api/characteristics/` (поиск по `code`).
- `GET /api/documents/`.
- `GET /api/audiences/`, `GET /api/audiences/menu/` — пункты навигационного меню.
- `GET /api/directions/`.

## Админка

- **Дашборд** на главной — сводка по серверу (CPU по load average, память, диск);
  данные отдаёт staff-only эндпоинт `/server-metrics/`, виджет обновляется раз в 5 с.
- **Категории** — дерево с перетаскиванием (`DraggableMPTTAdmin`) и кнопка
  «Пересобрать витрину».
- **Сортировка перетаскиванием** у брендов, характеристик, аудиторий и уровней
  групп (`django-admin-sortable2`).
- **Визуальный редактор** описаний (TinyMCE) с загрузкой картинок; отдельный
  загрузчик изображений товара с порядком.
- **Экспорт/импорт каталога в Excel** — кнопки на списке товаров.
- Динамическая форма характеристик по выбранной категории; автогенерация SKU;
  транслитерация slug из названия.

## Команды

- `python manage.py import_catalog products.json [--dry-run]` — массовый импорт
  карточек из старой JSON-выгрузки (`--dry-run` — прогон без записи).
- `python manage.py documents_expiring [--days N]` — отчёт по просроченным и
  истекающим документам (удобно повесить на cron).
- `python manage.py rebuild_storefront` — запуск пересборки витрины из CLI/крона.

## Быстрый старт (локально)

Подробно — в [SETUP.md](SETUP.md). Коротко: venv →
`pip install -r requirements.txt` → `migrate` → `createsuperuser` →
`runserver` → http://127.0.0.1:8000/admin/

## Рабочий процесс и деплой

Разработка локально → коммит и `push` в `main` на GitHub → деплой на VPS.
Развёртывание и автодеплой описаны в [DEPLOY.md](DEPLOY.md).

Через git едут **только код и миграции**. Базы данных и загруженные файлы
(`media/`) у каждой среды свои: локально — SQLite, на проде — PostgreSQL.
Схему на проде разворачивает `python manage.py migrate` из закоммиченных
файлов миграций. Секреты — в `.env` (в репозиторий не коммитятся); на проде
обязательно `DEBUG=0`.

## Связанная витрина

`profisfera-shop` — статическая витрина (SSG на GitHub Pages), которая собирается
из этого API. Пересборка запускается кнопкой «Пересобрать витрину» в админке
(на списках категорий и товаров) или командой `rebuild_storefront`; технически
это `repository_dispatch` в GitHub Actions витрины. PIM при этом остаётся
единственным источником данных о каталоге.
